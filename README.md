# wb-boss-widget

Chrome-расширение - полупрозрачный виджет для оперативного просмотра
показателей по нескольким кабинетам Wildberries (заказы, продажи,
маржа, остатки) без захода в отдельные Google-таблицы или личный
кабинет WB.

Контекст: это приватный инструмент под конкретную задачу (несколько
кабинетов, один пользователь). В перспективе на основе этого же
подхода планируется более крупный продукт - универсальный дашборд
контроля маркетплейсов для сторонних продавцов. Этот репозиторий
сознательно не пытается быть таким продуктом сразу: сначала -
рабочий инструмент под себя, потом - обобщение.

## Почему так сложно устроено

Казалось бы, самый простой путь - расширению напрямую ходить в WB
API и показывать данные. Мы намеренно так не делаем.

Причина: лимиты запросов к WB API на этих кабинетах уже почти
полностью заняты существующими выгрузками через Google Apps Script
в Google Sheets (десятки таблиц, обновляются ежедневно). Ещё один
источник запросов к тому же API создаст риск упереться в лимит и
сломать то, что уже работает.

Решение: не дублировать сбор данных, а переиспользовать то, что
уже есть. Подробнее - в `docs/adr/0001-reuse-google-sheets-instead-of-wb-api.md`.

## Как это устроено

1. Заказы/продажи: WB API -> Google Apps Script (уже существует, не трогаем) -> Google Sheets
2. Маржа: backend/ ходит в WB API напрямую (официальный отчёт о
   реализации, finance-api) - выручка, логистика, хранение, штрафы,
   реклама и прочие удержания, "к перечислению" считаются из него
   (формула сверена с итогом WB до копейки). Себестоимость - локальный
   `backend/data/costs.csv`. См. `docs/adr/0002-*` и `docs/adr/0003-*`
3. backend/ считает метрики (`app/metrics/`) и пишет в SQLite (`app/storage/`)
4. backend/ (FastAPI, `app/api/`) отдаёт готовый JSON
5. extension/ (Chrome, popup) опрашивает свой API при открытии, рисует цифры

Ключевой принцип: расширение не знает ни про WB, ни про Google
Sheets - оно просто раз в несколько минут спрашивает свой локальный
API "какие сейчас цифры" и рисует их. Все API-ключи и секреты живут
только на backend, в расширении их нет вообще.

## Хранение данных

Данные хранятся в SQLite в узком формате:

cabinet    date         metric    value
Cabinet1   2026-07-19   orders    142
Cabinet1   2026-07-19   sales     98500

Это осознанный выбор вместо широкой таблицы (кабинет-дата-заказы-
продажи-остатки-маржа в одной строке): метрики приходят из разных
источников не одновременно, и в узком формате отсутствие строки
однозначно значит "данных ещё нет", а не "данные - ноль". Хранится
вся история без ограничения по сроку (объём небольшой: несколько
кабинетов, несколько метрик, дни в году).

## Безопасность

- API backend'а биндится только на внутренний адрес рабочей сети,
  не смотрит в публичный интернет
- Дополнительно - API-токен на запросах от расширения
- В расширении секреты хранятся в chrome.storage.session
  (очищается при закрытии браузера), не в chrome.storage.local
- credentials.json (service account для Google Sheets API) и
  прочие секреты никогда не попадают в репозиторий (см. .gitignore)

## Структура репозитория

```
backend/
  app/
    config.py           # backend/.env: кабинеты, токены, cost-таблицы, API-настройки
    sheets_client.py     # общая авторизация и клиент Sheets API
    ingestion/           # чтение Sheets (архив), прямые вызовы WB API, cost-таблицы
    mapping/              # словари "заголовок источника -> каноническое имя"
    metrics/              # расчёт метрик (margin.py - revenue/cost/ad_spend/margin)
    storage/              # SQLite-слой (узкий формат cabinet/date/metric/value)
    api/                  # FastAPI-сервер для расширения
  scripts/                # разведочные/PoC-скрипты для ручной проверки (ходят в API)
  tests/                  # unit-тесты (pytest, без сети)
  requirements.txt
  cache/                  # кэш архивных листов и cost-таблиц (в .gitignore)
  data/                   # SQLite-база metrics.db (в .gitignore)
  credentials.json        # service account ключ (в .gitignore)
  .env                    # секреты и конфиг (в .gitignore, см. .env.example)
extension/
  manifest.json
  popup/                  # popup-окно: дёргает backend API при открытии
docs/
  adr/                   # архитектурные решения (контекст/решение/последствия)
```

Подробнее по каждой части - в `backend/README.md`, `extension/README.md`,
`docs/README.md`.

## Установка backend

```
pip install -r backend/requirements.txt
pytest backend/tests
```

## Статус

Полная цепочка работает end-to-end: реальные токены 4 кабинетов в
`backend/.env`, метрики считаются из официального отчёта о реализации WB
(`backend/app/metrics/margin.py`) и пишутся в SQLite, FastAPI отдаёт их
по API с токен-авторизацией, расширение установлено как unpacked
extension в Chrome и показывает цифры по кабинетам.

Загрузка (вручную, все кабинеты по очереди с паузой под лимит WB):

    cd backend
    .venv\Scripts\python.exe scripts\run_margin_ingest.py ALL 30

Известные упрощения/пробелы:
- Себестоимость - ручной `backend/data/costs.csv`; если артикула там
  нет, его себестоимость 0 (popup предупреждает "маржа завышена").
- Отчёт WB формируется по итогам недели - свежие дни появляются с
  задержкой до недели; автоматического расписания загрузки нет
  (решено пока не делать).
- Заказы/остатки (не только маржа) из корневого описания задачи - ещё
  не реализованы как метрики.
- `API_TOKEN` вводится на options-странице расширения и живёт в
  `chrome.storage.session` - после перезапуска Chrome его надо ввести
  заново (popup сам покажет кнопку «Ввести токен» на HTTP 401). Это
  осознанно: секрет не пишется на диск (см. "Безопасность").
