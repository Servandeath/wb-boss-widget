# ADR 0002: Прямые вызовы WB API из backend для маржи (в обход GAS)

## Статус

Принято

## Контекст

ADR 0001 решил не дублировать сбор данных и не ходить в WB API напрямую
из-за риска упереться в лимит запросов - лимит на кабинетах уже почти
полностью занят существующими выгрузками через Google Apps Script.

С тех пор ситуация изменилась: GAS-скрипты стали упираться в **свои**
квоты - квоты самого Google Apps Script (лимиты на количество вызовов
`UrlFetchApp`/время выполнения скрипта в сутки), а не в лимит WB API.
Владелец планирует постепенно переписывать GAS-скрипты на Python и
уходить из Google Sheets в отдельный микросервис - в рамках этого
проекта было решено начать этот переход с прототипа: маржа (revenue,
себестоимость, реклама) требует данных, которых в существующих
Google Sheets либо нет вообще (официальный WB "Отчёт о реализации" -
`reportDetailByPeriod` с разбивкой по комиссии/логистике/хранению/
штрафам), либо они собираются вручную из нескольких таблиц.

## Решение

`backend/app/ingestion/wb_client.py` ходит в WB API напрямую:

- `get_sales()` - `statistics-api/supplier/sales` (детальные продажи)
- `get_realization_report()` - `statistics-api/reportDetailByPeriod`
  (официальный отчёт о реализации - основной источник для маржи)

Себестоимость и расход на рекламу пока продолжают идти из Google Sheets
(`backend/app/ingestion/cost_sheets.py`, таблицы "Ультра" и "Реклама
общий" - см. `backend/.env`, `STOCK_SHEET_URL`/`ADS_AGGREGATOR_SHEET_URL`)
- своей системы учёта себестоимости и рекламы пока нет, эти таблицы
ведутся вручную.

Заказы/продажи по колонкам из `backend/app/mapping/wb_columns.py`
(`WB_COLUMN_MAP`) по-прежнему читаются из архивной Google-таблицы через
`backend/app/ingestion/sheet_reader.py` - этот путь не тронут, дублировать
его пока незачем.

## Последствия

- Плюс: маржа считается из официального источника WB, а не из ручных
  таблиц с риском рассинхрона/устаревших формул.
- Плюс: не зависим от лимитов Google Apps Script для этой части данных.
- Минус: и backend, и GAS теперь независимо расходуют один и тот же
  лимит запросов к WB API на кабинет - см. предупреждение в
  `backend/app/ingestion/wb_client.py` про `reportDetailByPeriod`
  (исторически ~1 запрос/минуту) и общее правило "аккуратно с лимитами"
  из памяти проекта - вызовы WB API в этом проекте только по одному за
  раз, без циклов/поллинга, пока не введена явная квота/расписание.
- Минус: два источника правды на переходный период (GAS всё ещё пишет
  часть тех же данных в Sheets) - осознанно, это первый шаг постепенного
  вывода из GAS, не одномоментная замена.
- Открытый вопрос на будущее: перенести себестоимость/рекламу из ручных
  Google Sheets в свою систему - см. `docs/wb_gas_prototype/` (не в
  git) и память проекта (`ref-fin-otchet-sheet`, `ref-reklama-obshiy-sheet`).
