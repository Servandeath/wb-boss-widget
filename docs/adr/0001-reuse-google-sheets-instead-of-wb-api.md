# ADR 0001: Переиспользовать Google Sheets вместо прямых запросов к WB API

## Статус

Принято

## Контекст

Самый простой путь для виджета - самому ходить в WB API и показывать
данные. Но лимиты запросов к WB API на используемых кабинетах уже почти
полностью заняты существующими выгрузками через Google Apps Script в
Google Sheets (десятки таблиц, обновляются ежедневно). Ещё один источник
запросов к тому же API создаёт риск упереться в лимит и сломать то, что
уже работает.

## Решение

Не дублировать сбор данных, а переиспользовать то, что уже есть:

1. WB API -> Google Apps Script (уже существует, не трогаем) -> Google Sheets
2. `backend/` (cron, раз в день) читает Sheets API, считает метрики, пишет в SQLite
3. `backend/` (FastAPI) отдаёт готовый JSON
4. `extension/` (Chrome) опрашивает свой API, рисует виджет

Расширение не знает ни про WB, ни про Google Sheets - оно просто
опрашивает свой локальный API "какие сейчас цифры" и рисует их. Все
API-ключи и секреты живут только на backend.

## Последствия

- Плюс: не расходуем и так почти исчерпанный лимит WB API.
- Плюс: расширение проще и безопаснее - в нём вообще нет секретов.
- Минус: лишний слой (backend с cron и своей БД) вместо прямого запроса
  из расширения - больше кода и его нужно где-то держать запущенным.
- Минус: данные в виджете не более свежие, чем последнее обновление
  Google-таблицы через Apps Script (сейчас - раз в день).
