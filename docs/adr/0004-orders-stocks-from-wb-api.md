# ADR 0004: Заказы и остатки напрямую из WB API (Order Feed, отчёт об остатках)

## Статус

Принято. Заменяет путь "заказы/продажи через GAS -> Google Sheets" из
ADR 0001/0002 для backend.

## Контекст

По исходной задаче виджет показывает заказы и остатки, а не только
маржу. ADR 0002 оставлял заказы в архивной Google-таблице (её пишет
GAS). С тех пор:

- таблицы владелец перенёс и переделал - для backend они не актуальны;
- WB выпустил Order Feed (`POST seller-analytics-api/api/analytics/v1/order-feed`,
  2026-08) - лента заказов в реальном времени со статусами, на замену
  `supplier/orders` и `supplier/sales`, которые WB обещал отключить;
- для остатков на складах WB есть `POST .../stocks-report/wb-warehouses`
  (обновляется раз в 30 минут).

Оба метода - категория токена "Аналитика", она есть у всех токенов
кабинетов.

## Решение

`backend/app/metrics/orders_stocks.py`, загрузка -
`scripts/run_orders_stocks_ingest.py`:

- заказы по дню `createdAt` (МСК): orders, orders_sum (sellerPrice),
  cancels/buyouts/returns по ТЕКУЩЕМУ статусу заказа;
- остатки - снимок на момент загрузки, пишется на сегодняшнюю дату:
  stock, stock_to_client, stock_from_client (склады WB) и stock_seller
  (`stocks-report/seller-warehouses`, свои склады продавца - у МАНИ
  ~14% заказов идут с FBS-склада).

Особенности Order Feed, найденные на реальных данных:

- период фильтрует по времени текущего статуса, а не по `createdAt` -
  в окно попадают старые заказы, сменившие статус (видели августовские
  в выгрузке за 3 дня октября). Дни раньше начала окна неполные и не
  пишутся;
- `limit` максимум 10 000 (больше - 400), лимит 1 запрос/минуту,
  максимум 31 день назад; пагинация offset от одного `snapshotTime`.

## Последствия

- Плюс: оперативные цифры без GAS и Google Sheets.
- Минус: cancels/buyouts за свежие дни растут после загрузки - чтобы
  они обновлялись, загрузку надо перезапускать (расписания пока нет).
- Минус: история остатков есть только за дни, когда запускалась загрузка
  (WB отдаёт только текущий снимок).
