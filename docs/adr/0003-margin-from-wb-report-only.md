# ADR 0003: Маржа целиком из отчёта о реализации WB, себестоимость из локального CSV

## Статус

Принято. Уточняет ADR 0002 (часть про Google Sheets больше не действует).

## Контекст

ADR 0002 брал из отчёта о реализации только строки "Продажа" и
`forPay`, а себестоимость и рекламу - из ручных Google Sheets ("Ультра",
"Реклама общий"). В 2026-10:

- WB отключил `statistics-api/reportDetailByPeriod`, отчёт переехал в
  `finance-api/api/finance/v1/sales-reports/detailed` (поля в camelCase,
  денежные - строками, пагинация по `rrdId` до 204);
- таблицы владелец перенёс и переделал - для backend они не актуальны
  (сервисный аккаунт получает 403);
- разбор реального отчёта показал, что реклама, оплаченная с баланса WB,
  уже есть в отчёте - удержания с `bonusTypeName` "WB Продвижение" /
  "WB Медиа" (у МАНИ это ~90% всех удержаний).

## Решение

Все денежные метрики считаются из отчёта о реализации
(`backend/app/metrics/margin.py`, формула - в его докстринге):
revenue, logistics, storage, acceptance, penalties, ad_spend,
deductions, loyalty, additional -> payout ("к перечислению") -> margin.

Формула сверена с официальным итогом WB `bankPaymentSum` из
`/sales-reports/list`: на всех полных отчётах МАНИ за 3 недели
совпадение до копейки. Найденные по пути тонкости:

- знак "минус" определяется по `docTypeName == "Возврат"`, а не по
  `sellerOperName` - иначе не сходятся возвраты баллов лояльности;
- `rebillLogisticCost` в итог WB не входит - справочное поле;
- день - `rrDate`, а не `saleDt`: WB фильтрует строки по `rrDate`, а
  `saleDt` у возвратов/удержаний бывает на месяцы раньше периода -
  ключ по нему затирал бы уже загруженные дни частичными суммами.

Себестоимость - `backend/data/costs.csv` (`nm_id;tech_size;cost`, в
.gitignore; пример - `costs.example.csv`). Нет файла или артикула -
себестоимость 0, а метрика `units_without_cost` показывает, сколько
единиц не покрыто (popup предупреждает, что маржа завышена).

## Последствия

- Плюс: Google Sheets для маржи больше не нужны; `cost_sheets.py` и
  сервисный аккаунт для этого пути не используются.
- Плюс: формула проверяема - есть официальный итог WB для сверки.
- Минус: удержания (реклама, подписки) WB выставляет документами раз в
  несколько дней - по дням ad_spend "ступенчатый", точен на неделе.
- Минус: отчёт формируется по итогам периода (weekly - по понедельникам),
  последние дни появляются с задержкой. Для оперативных цифр позже -
  `period: "daily"` или Order Feed (`/api/analytics/v1/order-feed`).
- Минус: реклама, оплаченная не с баланса WB (картой/счётом), в отчёт
  не попадает - если такая есть, её нужно будет добавить отдельным
  источником.
- Справочник себестоимости ведётся вручную в CSV до появления своей
  системы учёта.
